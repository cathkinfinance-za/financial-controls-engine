3. Core Operational Regulations

3.1 The Anti-Splitting Directive

Large projects, single procurement orders, or related service invoices may not be split into multiple smaller purchase orders or partial payments to circumvent the threshold limits defined in Section 2. Threshold compliance is determined by the total cumulative cost of the required work or asset procurement.

3.2 Procurement Sourcing Thresholds

  • Transactions under R10,000: A single written quote from an approved, accredited estate vendor.
  • Transactions from R10,001 to R50,000: A minimum of two independent written quotes must be evaluated.
  • Transactions over R50,000 / Capital Tenders: A minimum of three independent written quotes accompanied by a detailed comparison (system-generated) must be submitted to the Finance Committee.

4. Compliance Status Engine: Evaluation Phases

Phase 1: Terminal States (Overriding Blocks)

Before running any validation rules or calculating threshold limits, the system checks whether a transaction has already been concluded. If a transaction has a final resolution, further system analysis is bypassed:

  • Approved State: If the Submission Status is marked as "Approved", the engine immediately locks the status as: ✅ APPROVED: Compliance Process Complete
  • Rejected State: If the Submission Status is marked as "Rejected", the engine immediately locks the status as: 🛑 REJECTED: Final Authorisation Declined

Phase 2: Mandatory Metadata Validation (Quality Gates)

If the transaction is active (not resolved), the system forces the operator to provide accurate general ledger and category mapping. The status is flagged with a Warning (⚠️) if any crucial parameters are missing:

  • General Ledger Check: If the purchase is budgeted (Has this been budgeted for? = "Yes") but the General Ledger field Select GL Code is blank or returns a calculation error: ⚠️ ACTION REQUIRED: Select a valid GL description
  • Expense Classification Check: If the Expense Type field is left blank: ⚠️ ACTION REQUIRED: Select Expense Type If Not Approved
  • Quote Quantification Check: If the Quotes Provided count field is left blank: ⚠️ ACTION REQUIRED: Enter number of quotes provided

Phase 3: Procurement Compliance Hard-Stops

To enforce fair value and prevent direct single-vendor bias, the engine verifies the quantity of quotes provided against the transaction’s value. If the quotes do not match the required thresholds, the transaction is Blocked (❌):

  • Under R10,000: Requires a minimum of 1 quote. If 0 quotes are entered, the transaction is blocked.
  • R10,001 to R50,000: Requires a minimum of 2 independent quotes. If fewer than 2 are entered, the transaction is blocked.
  • Over R50,000: Requires a minimum of 3 independent quotes. If fewer than 3 are entered, the transaction is blocked.
  • Capital Expenditure & Infrastructure (Any Amount): Always requires a minimum of 3 independent quotes. If fewer than 3 are entered, the transaction is blocked.
  • Status Output if Sourcing Rules are Violated: ❌ BLOCKED: Insufficient Quotes Provided for this Threshold

Phase 4: AI Sourcing Matrix Verification

For high-value or long-term structural decisions, human assessment alone is insufficient. The engine enforces the generation of an objective AI-powered comparative matrix:

  • AI Matrix Gate: If the Estimated Cost exceeds R50,000, or if the Expense Type is categorized as "Capital Expenditure & Infrastructure", and the Procurement Matrix Summary Chart remains blank (indicating Python script 4_AI_Matrix_Drafter.py has not run yet): 📋 ACTION REQUIRED: Run Python AI Sourcing Matrix via Projects

Phase 5: Routing Pathways & Approval Thresholds

Once a transaction has passed all metadata, sourcing, and AI verification gates, the system assigns the appropriate routing pathway based on the budget status and expenditure category:

A. Special Non-Standard Classifications

  • Capital Reserve Outlays: If the Expense Type is "Capital Expenditure & Infrastructure": 🏦 Capital Expenditure: Reserve Allocation (Requires Full Board & AGM Ratification)
  • SLA Service Provider Appointments: If the Expense Type is "Service Provider Contracts": 📝 Service Provider Contract: SLA Appointment (Requires Full Board Dual Signatures)

B. Standard Budgeted Expenditure (Has this been budgeted for? = "Yes")

  • Up to R10,000: 🟢 Routine Operational: Within Budget (No Approval Required) (Auto-authorized for reconciliation log).
  • R10,001 to R50,000: 🟡 Portfolio Operational: Within Budget (Requires Chairman Sign-off)
  • Over R50,000: 🟠 High-Value Operational: Within Budget (Requires 2 Board Members)

C. Unbudgeted Emergency Expenditure (Has this been budgeted for? = "No" AND Expense Type = "Emergency")

  • Up to R30,000: ⚡ Emergency Expenditure: Unbudgeted (Requires Ops & Board Chair Ratification)
  • Over R30,000: ❌ EMERGENCY CRITICAL: Exceeds R30,000 Limit (Requires Urgent Board Resolution) (Hard-locked to prevent unauthorized emergency spending).

D. Unbudgeted Extraordinary Expenditure (Has this been budgeted for? = "No" AND Expense Type = "Extraordinary")

  • Up to R30,000: 🔵 Extraordinary / Unbudgeted: (Requires Full Board Written Motivation)
  • Over R30,000: ❌ UNBUDGETED BLOCKED: Exceeds R30,000 Limit (Requires AGM Ratification) (Hard-locked to enforce AGM statutory limits).

5. Special Safeguard: The 2-Month Run-rate Buffer Pool (2M Pool)

The system incorporates an independent, macro-liquidity evaluation variable: the {2M Buffer Pool}. This represents a baseline cash reserve equivalent to two months of standard operational estate expenditures.

  • Programmatic Application: While the Airtable logical formula governs sequential routing thresholds, the automation script 2_send_approvals_airtable.py leverages this field to prevent structural deficits.
  • Dynamic Health Audit: During step 2 (Inbound Dispatch & AI Audit), the Python logic compares the post-purchase remaining balance of the target GL code against the {2M Buffer Pool} reserve.
  • Deficit Risk Warnings: If the post-purchase balance falls below the 2-Month Run-rate threshold, the AI automatically overrides a standard "Approved" narrative to attach a highly visible Fiscal Vulnerability Alert to the Board’s routing email. This ensures that even "within-budget" expenses are scrutinized if they threaten the estate's overall operational runway.
